# Contributing to SecondCheck

Thank you for considering a contribution. Please use a focused branch, keep each pull request small, and describe the user-visible effect and any relevant limitations.

## Before opening a pull request

1. Review the existing behavior and avoid unrelated formatting changes.
2. Add or update tests for changed behavior where practical.
3. Run `npm run typecheck`, `npm run lint`, the relevant `npm run test:*` commands, and `npm run build:web`.
4. For interface changes, check mobile and desktop layouts in both themes and include screenshots when they help reviewers.
5. Do not commit credentials, `.env` files, signing keys, generated output, or `node_modules`.

## Pull requests

Explain what changed, why it changed, how it was tested, and any follow-up work. Keep product claims appropriately qualified: valuation, condition, and risk results are decision support rather than guarantees. Maintainers may request tests, documentation, or smaller commits before merging.
